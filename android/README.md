# Android app

A WebView around `https://play.fluxious-rsps.com`, and nothing else. The client, its assets and its
cache all arrive over HTTPS at runtime, so this app never needs rebuilding when the game changes —
only when the wrapper or its icons do.

There are no dependencies, not even AndroidX: one `Activity`, one `WebView`.

## Building

CI builds it on any push touching `android/`, and on demand from the Actions tab, where the start
URL can be overridden for a test build. Two artifacts come out:

| Artifact | Signed with | Use |
|----------|-------------|-----|
| `fluxious-debug-apk` | the standard Android debug key | installs straight from the artifact |
| `fluxious-release-apk-unsigned` | nothing | needs signing before it will install |

Locally, with an Android SDK installed:

```bash
cd android
gradle assembleDebug
gradle assembleDebug -Pflux.startUrl=http://10.0.2.2:5173   # a dev server, from the emulator
```

## Signing a release

The release APK is deliberately unsigned rather than signed with a key committed to the repo. To
ship one, sign it with your own keystore:

```bash
apksigner sign --ks fluxious.jks --out fluxious.apk app-release-unsigned.apk
```

Use the same keystore every time: Android identifies an app by its signature, and a release signed
with a different key cannot upgrade one signed with the old one — players would have to uninstall
and lose their saved logins.

## Minimum Android version

`minSdk 21` (Android 5.0). The wrapper itself would run on much older Android; the limit is the
WebView. From 5.0 the system WebView is a separately updatable Play package and can be a current
Chromium, while on 4.4 it is frozen at Chromium 33, which cannot run the client. A lower floor would
produce an app that installs and then fails.

That also means the Android version is not the whole story: a 5.0 device whose WebView has never
updated will still fail. What matters is the WebView version, which players can check and update
from Play under "Android System WebView".

## Icons

Generated by `tools/make-icons.sh` from `art/`, run by CI before the build rather than committed as
output — changing the art is the whole change.

- `art/f2_big.png` — square, with its own rounded corners. Used as-is for the legacy mipmaps.
- `art/Flux-Icon2.png` — a round badge on a transparent field. Used for the adaptive foreground,
  scaled into the middle 66% of a 108dp canvas because an adaptive icon is masked to whatever shape
  the launcher chooses and only that centre is guaranteed to survive.

## HTTPS

The start URL is `https://`, and cleartext is left blocked — Android's default since API 28.

Keep it that way. A page served over plain HTTP is not a secure context, so the browser withholds
the Origin Private File System and the client falls back to IndexedDB for its cache
(`web/vfs.js:59`) — the same data, but every read through an async store instead of a sync file
handle. The site redirects HTTP to HTTPS anyway, so an `http://` start URL would only buy a wasted
round trip on launch.
